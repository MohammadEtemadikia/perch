# Setup

## Requirements

- Node.js 20+
- macOS, Windows, or Linux (the desktop shell targets all three; only macOS has been actually run and verified so far)
- `git` on PATH (used read-only for the Git tab and changelog import)

## First run (web dev mode)

```bash
npm install
npm run db:seed     # populates the DB from scripts/seed.ts — safe to skip, safe to re-run
npm run dev          # http://localhost:4100
```

The database lives at `./data/perch.db` in this mode. Delete it (or run `npm run db:reset`) to start over.

## Running as the actual desktop app

```bash
npm run app
```

This runs `npm run build:app` first, which does more than a plain `next build` — see below.

## Building distributable installers

```bash
npm run package:mac     # .dmg, arm64 + x64, unsigned (identity: null in electron-builder.yml)
npm run package:win     # NSIS installer + portable .exe
npm run package:linux   # AppImage
```

**Verified so far:**
- `package:mac` produces `dist/Perch-<version>-arm64.dmg` and `dist/Perch-<version>.dmg`. Both were actually built, the arm64 build's unpacked `.app` was launched directly (not just `npm run app`), seeded, and confirmed to serve all 10 real projects with no errors — this is the same binary a user gets from the DMG.
- `package:win` produces `dist/Perch Setup <version>.exe` (NSIS installer) and `dist/Perch-portable-<version>.exe`. These were built successfully cross-platform from this Mac and confirmed to be well-formed Windows PE executables, but **were never actually run** — there was no Windows machine available to test on. Building Windows targets from macOS requires Wine (electron-builder downloads its own copy) which in turn requires Rosetta 2 on Apple Silicon — if you see `cannot execute ... bad CPU type in executable`, run `softwareupdate --install-rosetta` first.
- `package:linux` has not been run or verified at all.

The app icon is real (`build/icon.icns` for mac, `build/icon.ico` for Windows, `build/icon.png` for Linux — all generated by `npm run generate-icons` from `build/icon-source.svg`), and is wired into `electron-builder.yml`, the app window (`electron/main.cjs`), and the web favicon (`src/app/layout.tsx`). To change the icon, edit `build/icon-source.svg` and re-run `npm run generate-icons`.

## The native-module rebuild step (important)

`better-sqlite3` is a native addon. It must be compiled for:
- the **system Node ABI** to run under `next dev` / `next build` / `npm run db:seed`
- **Electron's own ABI** to run inside the packaged app

These are different, and using the wrong one produces a startup crash (`ERR_DLOPEN_FAILED`, `NODE_MODULE_VERSION` mismatch) — this happened once during development. `npm run build:app` runs the correct sequence automatically:

```
rebuild:node → next build → rebuild:electron → prepare-server.mjs → rebuild:node
```

If you ever run `electron-rebuild` manually, or run `electron-builder` directly instead of through `npm run package:*` (electron-builder does its own internal native-module rebuild), and then go back to `npm run dev` without also running `npm run rebuild:node`, `next dev`/`npm run db:seed` will fail to load the database. The fix is just:

```bash
npm run rebuild:node
```

## Environment variables

Perch has none of its own — no `.env` file is required to run it. (It reads other projects' `.env`/`.env.local`/`.env.example` files to report *variable names only*, never values, and never writes to them.)

## Resetting everything

```bash
npm run db:reset     # deletes the local SQLite file
npm run db:seed       # repopulates from scripts/seed.ts
```
